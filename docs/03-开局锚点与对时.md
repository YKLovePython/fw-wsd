# 03 · 开局锚点与对时

## 1. 问题：谱面 0 点在哪

谱面文件里所有时间都是**相对音乐 0 点**的，但它没告诉你"按下 LIVE START 之后
多久音乐才开始"。加载时长取决于设备、缓存、后台，实测同一台机器同一天：

```
2.12s  9.53s  10.05s  11.52s
```

差了 9 秒。任何"点完按钮等 N 秒"的做法都是掷骰子，而且**整首歌会一起偏**，
不是漏一两个音。

所以锚点必须**从画面里量**。

## 2. 两条互相独立的尺子

演奏开始前，画面只有两个可靠事件：

| 事件 | 信号 | 换算 |
| --- | --- | --- |
| **加载页结束**（整屏由亮变黑） | 整帧亮度 ~203 → <1，信号极大 | `t0 = 亮页结束 + 5.9167s`（355 帧 @60fps，开场动画固定长度，播完即开音乐） |
| **判定线出现**（演奏画面） | 白线 + 品红线同时淡入 | `t0 = 穿越点 + 0.1967s`（用录像里音符真正压线的时刻反推） |

演奏画面的判据必须是**两条横线同时存在**：上白线 ≈ 0.755 屏高、下品红线 ≈ 0.835 屏高。
只有一条时会被加载页的进度条骗到。

### 为什么两条都要留

* 判定线只淡入 1~2px，**最怕掉帧**；掉几帧后取中点，最多能偏半帧（60fps 下 ≈83ms）。
* 加载页是整屏亮→黑，掉几帧也不怕。

所以：**默认用加载页锚点**（稳的那把尺子），判定线锚点做交叉校验；
判定线不可信（0.5 穿越不是在连续稠密帧里看到的 / 帧率塌了）时才回退。

> 1.4.7 之前的版本这里多了一行 `!trusted`，意思是"判定线看起来可信时反而放弃
> 加载页"。这就是把稳的尺子扔了、只剩最敏感的那把，掉帧局必崩。删掉那一行就对了。

### 交叉校验

两条尺子量的是同一个 `t0`，实测只差 **~30ms**。所以：

* 差 ≤ 阈值 → 加载页锚点可用；
* 差好几秒 → 那个"亮页"根本不是加载页（确认页/选曲页的过场），宁可不用。

每局把**所有**亮→黑事件都记下来（`[亮页结束, 预测 t0, 持续秒数]`），
最后挑"离判定线锚点最近"的那个 —— 过场页预测出来的 `t0` 会差好几秒，自然被排除。

## 3. 亚帧插值

不能只用"分数 ≥ 0.5 的那一帧"，否则误差是半帧。做法是：

1. 连续分数 `min(品红覆盖率/0.45, 白线覆盖率/0.30)`；
2. 找分数**穿过 0.5** 的前后两帧，线性插值出穿越时刻；
3. 判断这次定位可不可信：
   * 跨距 ≤ 2~3 个帧间隔（连续稠密帧）→ 可信；
   * 一帧从无到满（硬切）→ 跨在相邻两帧之间时中点无偏，也可用；
   * 跨距明显变大 / 帧率已塌（静态画面 100ms 重复帧）→ **标记不可信**。

日志里会打一行"锚点体检"：

```
锚点：加载页 已用，差 −34ms，帧间隔 16.7ms，斜坡 跨距 3 帧 → 可信
```

以后出现"整首偏早/偏晚"，看这一行就能分清是哪一环：

| 症状 | 结论 |
| --- | --- |
| 帧间隔 50~100ms | 画面掉帧，锚点本身就不准 |
| 斜坡是"跨距过大→中点" / "看不到起点" | 淡入被跳过了 |
| 加载页差 +80~150ms 且"已改用加载页" | 判定线确实晚了，已自动修正 |
| 标记可信、帧间隔正常 | 锚点没问题，去查注入/游戏本身 |

## 4. 手机版为什么少了一整项误差

PC 版的时间轴是：`perf_counter`（电脑）→ 视频包到达时刻 → 解码 → 算 `t0`
→ 减 `pipeline_lag_ms` → 注入。中间有"画面链路延迟"必须靠 `fw-wsd calib` 实测扣掉。

手机版直接用**视频帧自带的 `pts`（微秒）**，它和 `System.nanoTime()` 同源 ——
所以**没有"画面链路延迟"这一项可扣**。这是手机版比 PC 版更准的根本原因，
不是算法更好。

## 5. 对账日志

每局开始打一行，结算页的 miss 数可以直接对这张表：

```
谱面：100040 / EXPERT，1889 个动作，offset 0ms
  对账：音符 715（tap 508 · flick 67 · 长条 140）｜guide 0 / 116 条
          · trace 8 / 41 条（含 auto 滑条 1）· critical 10
```

`guide 0 / 116` 里的 116 是**容器总数**，0 是"我们主动发的"，
不是漏了 116 个 —— 这一点很容易看错。真正表示漏发的是 `trace 8 / 41`：
分子是发出去的条数，分母是谱面里 trace 节点串起来的条数。

打完还有一行：

```
注入完成 1889 个动作，最迟 +3.2ms（p95 +1.4ms）
```

`p95` 大 → 查时序（线程调度/锚点）；`p95` 小 → 一定是手势判定问题，不是时间问题。
**先看这两行再猜**，能省掉一半排查。
