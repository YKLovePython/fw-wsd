# fw-wsd 技术笔记总览

这套东西做的是同一件事：**在没 root 的 Android 手机上，让游戏自己把一首音游玩完。**
两代实现共用一套谱面解析与排程内核：

| 代 | 跑在哪 | 一句话 |
| --- | --- | --- |
| PC 版 | Windows + USB/无线 ADB | 电脑解码视频流做首音符对时，手机只负责被注入 |
| 手机版（`klkldkdk`，1.5.1） | 手机自己 | 同机内 `adb` 自己连自己，视频自己解、手指自己发 |

下面的笔记只写**可复用的那部分**：格式怎么反推出来的、判据为什么是这条、
哪些做法被证伪了。踩坑记录比结论更值钱，所以单独一篇。

## 一句话结论（先看这个）

1. **`guide` 不等于音符。** 614 条 guide 里只有 41 条含 `trace` 节点、253 条含
   `positionAuto` 节点，剩下 328 条是视觉参考线。把 614 条全发＝开局按 3 指 10 秒、
   整局全 miss（1.4.9c，已实测）。
2. **判定线位置可以直接算，不用校准。** 游戏自己的场景数据：判定平面挂在相机前
   `10.6078`、视锥半高 `5.4048` ＝ 平面半高 `5.4`，所以平面 1:1 铺满屏高，
   判定线恒在 `79.259%` 屏高处。
3. **首音符时间只能量，不能猜。** 同机同日实测"点完 LIVE START 到音乐开始"在
   `2.12s / 9.53s / 10.05s / 11.52s` 之间摆——差了 9 秒，任何固定等待都是掷骰子。
4. **长条要按距离重采样。** 谱面节点 ≈157ms 一个，一次跳变中位数 197px，
   和音符自身命中宽度同量级，所以"每个节点挪一次手指"会间歇性掉。
   改成每移动 ~50px 补一个 `move`，中位步长降到 72px。
