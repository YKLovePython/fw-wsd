## 2. 生成 assets

谱面不进 Git。构建前先跑一次生成：

```powershell
$env:FW_WSD_GUIDE="off"; $env:FW_WSD_TRACE="hold"
python android\tools\gen_assets.py
```

输出 `android/app/src/main/assets/charts/<musicId>_<diff>.json`，每张谱的 `meta`：

```json
{"n": 715, "tap": 508, "flick": 67, "long": 140,
 "guide": 116, "guideVis": 36, "guidePlay": 0,
 "trace": 41, "tracePlay": 8, "traceAuto": 1, "crit": 10}
```

* `guide / guideVis` = guide 容器总数 / 其中可见节点数（**参考价值，不是音符数**）
* `guidePlay` = 实际发出去的 guide 长条（默认策略下为 0）
* `trace / tracePlay / traceAuto` = trace 串总数 / 发出去的 / 其中来自 `positionAuto` 的
* `acts` 数组 = `[t, kind, slot, x, y]`，`kind` ∈ `down|move|up`

全库规模：**96 首 / 384 张谱 / 382,821 个动作 / 9.6 MB**。

两个开关（`FW_WSD_GUIDE` / `FW_WSD_TRACE`）留着做对照实验：

| 值 | 语义 |
| --- | --- |
| `GUIDE=off`（默认） | guide 整类跳过，只发 trace/auto |
| `GUIDE=b1` | 所有 guide 当长条（1.4.9c，已证伪，仅作对照） |
| `GUIDE=tap` / `slide` | 1.4.9a / 1.4.9b 的旧行为 |
| `TRACE=off` | trace 整类跳过（对照组） |
| `TRACE=hold`（默认） | trace → 按住 + 走轨迹 |

## 3. 编译

```powershell
$env:JAVA_HOME="C:\...\jdk-17.0.21+9"
$env:ANDROID_HOME="C:\...\sdk"
gradle -p android assembleRelease --no-daemon --console=plain
```

输出 `android/app/build/outputs/apk/release/app-release.apk`（约 75 MB，主要是
`libadb.so` × 2 + onnxruntime + scrcpy-server + 9.6 MB 谱面）。

> Gradle 在 PowerShell 里可能返回 `Exit code: 1`，但上面已经打印
> `BUILD SUCCESSFUL` —— 这是 PowerShell 对 stderr 的处理，不是构建失败。

## 4. 验包（四条命令）

```powershell
aapt2 dump badging  dist\fw-wsd-android-v1.5.1.apk   # versionCode / label
apksigner.bat verify --print-certs dist\fw-wsd-android-v1.5.1.apk   # 签名指纹
Get-FileHash dist\fw-wsd-android-v1.5.1.apk -Algorithm SHA256       # 分发用哈希
```

再抽查一次资产内容，确认打进去的是新版而不是缓存：

```python
import zipfile, json
z = zipfile.ZipFile("dist/fw-wsd-android-v1.5.1.apk")
d = json.loads(z.read("assets/charts/100040_expert.json"))
print(len(d["acts"]), d["meta"]["traceAuto"])   # 1889 1
```

## 5. 签名

`android/app/keystore/fwwsd.jks`，`keyAlias=fwwsd`。

**仓库里不带 keystore、不带口令。** 本地构建时把 `storePassword` / `keyPassword`
放进 `keystore.properties`（不提交），或改成读环境变量。
换签名后无法覆盖安装，必须先卸载 —— 所以发布前一定确认用的是同一把钥匙。
